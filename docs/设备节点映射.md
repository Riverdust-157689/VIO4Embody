# /dev/video* 设备节点映射方法（udev 固定设备名）

> 适用：YLX-2UQ2 双目相机，以及任何 UVC 摄像头拔插后节点漂移的问题。

## 一、问题背景

Linux 的 UVC 摄像头按枚举顺序分配 `/dev/videoX`（video0、video1...）。**拔插、重启、多摄像头接入都会导致节点号漂移**：

```
第一次插上:  2UQ2 在 /dev/video2
拔插后重排:  2UQ2 变成 /dev/video0   ← 驱动/脚本里写死的 video2 就失效了
```

本项目的真实踩坑：驱动曾因节点漂移报 `VIDIOC_S_FMT: Invalid argument`（打开了错误的视频节点）。

## 二、确认设备当前节点（排查第一步）

```bash
v4l2-ctl --list-devices
# 输出示例:
# 2UQ2: 2UQ2 (usb-0000:00:14.0-2):
#     /dev/video2
#     /dev/video3
#     /dev/media1

lsusb
# 找到 2UQ2 的 USB ID: "1bcf:0b15 Sunplus Innovation Technology Inc. 2UQ2"
#   idVendor=1bcf  idProduct=0b15
```

> 每个 UVC 摄像头通常有 **2 个 video 节点**：videoN（采集节点，有 XU）和 videoN+1（metadata 节点，无 XU）。**只有采集节点能设格式/读 XU**，映射规则必须只匹配采集节点（见下文 `ATTR{index}==0`）。

## 三、解决方案：udev 规则生成稳定符号链接

### 规则文件（本仓库已带）

`tools/2uq2_probe/99-2uq2.rules`：

```
SUBSYSTEM=="video4linux", KERNEL=="video*", ATTRS{idVendor}=="1bcf", ATTRS{idProduct}=="0b15", ATTR{index}=="0", SYMLINK+="video2uq2", MODE="0666"
```

| 匹配项 | 含义 |
|---|---|
| `SUBSYSTEM=="video4linux"` | 只匹配 video4linux 子系统 |
| `KERNEL=="video*"` | 节点名为 video* |
| `ATTRS{idVendor}=="1bcf"` | **父设备**（USB）厂商 ID = 1bcf（Sunplus） |
| `ATTRS{idProduct}=="0b15"` | 产品 ID = 0b15（2UQ2） |
| `ATTR{index}=="0"` | **只匹配采集节点**（index=0；metadata 节点 index=1，会建到错误节点上导致 S_FMT 失败） |
| `SYMLINK+="video2uq2"` | 生成稳定链接 `/dev/video2uq2` |
| `MODE="0666"` | 所有人可读写（省去 video 组/root 权限问题） |

### 安装步骤

```bash
# ① 复制规则
sudo cp ~/vision_imu/VINS-Fusion/tools/2uq2_probe/99-2uq2.rules /etc/udev/rules.d/

# ② 重载规则并触发
sudo udevadm control --reload-rules
sudo udevadm trigger --attr-match=subsystem=video4linux
# 若链接没出现, 拔插一次摄像头(或重启)即可

# ③ 验证(应指向采集节点 video0/video2 之类, 而不是 metadata 节点)
ls -l /dev/video2uq2
# 期望: lrwxrwxrwx ... /dev/video2uq2 -> video0
```

> 若链接指向了 metadata 节点（video1/video3），说明规则没生效或匹配了多个节点：先 `sudo udevadm control --reload-rules`，再拔插摄像头。

## 四、规则对其他设备的扩展

换设备只需改 `idVendor/idProduct`（`lsusb` 查）和 `SYMLINK` 名字，其余照抄：

```
SUBSYSTEM=="video4linux", KERNEL=="video*", ATTRS{idVendor}=="<VID>", ATTRS{idProduct}=="<PID>", ATTR{index}=="0", SYMLINK+="video<名字>", MODE="0666"
```

## 五、Docker 容器透传

用稳定链接而不是 videoX，容器里永远是同一个设备名：

```bash
docker run ... --device /dev/video2uq2 ...
```

本项目脚本已统一使用 `/dev/video2uq2`（`run_foxglove.sh` / `run_shell.sh` 会自动检测存在才透传）。

## 六、排查速查

| 现象 | 处理 |
|---|---|
| 驱动报 `VIDIOC_S_FMT: Invalid argument` | 链接指向了 metadata 节点 → 重装规则 + 拔插 |
| `/dev/video2uq2` 不存在 | 规则未安装/未触发 → 重装 + `udevadm trigger` |
| 插了多台同型号相机 | 规则会都映射到同一链接 → 需按 USB 端口区分（`KERNELS=="pci-*:00:14.0-2"` 之类，进阶需求） |
| 权限拒绝 | 规则已带 `MODE="0666"`；旧规则可加 `sudo chmod 666 /dev/video*` 临时验证 |
